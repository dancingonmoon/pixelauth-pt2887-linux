# PXAT 协议笔记 —— 品识 PT2887-SS 指纹模组（逆向与实测整理）

> 来源：对**自有设备**的 USB 抓包（usbmon）、随附软件公开日志的观察、大量控制实验。
> 整理出来供互操作与学习研究。有疑问以你自己设备上的实测为准。
>
> 设备：USB `2f0a:8020`（"PXAT PT2887-SS Module"），电源键二合一，
> **match-on-chip**（模板在芯片里，有 10 个槽位：10–19），批量传输。

---

## 1. 传输层：帧格式

所有命令走同一个"信封"：

```
[0..4]   "PXAT" + 0xC0
[5..6]   BE16 内层长度 = 10 + payload_len   ★ 必须包含末尾 2 字节 CRC！
[7..13]  EF 01 FF FF 00 00 00
[14]     payload_len（u8）
[15..]   payload
[末2]    BE16 CRC-16/KERMIT（只对 payload 计算，大端存放）
```

- 端点：**`0x02` OUT / `0x81` IN**，bulk。
- **头号大坑：`inner_len` 漏算 CRC 的 2 字节** → 设备一律回 9 字节 NAK
  （`50584154 c0 0002 9fff`），表现像"设备不理人"。
- 响应同样是这个信封；响应 payload 的首字节通常是状态码。

## 2. 命令表（实测）

| 命令 | payload | 作用 |
|---|---|---|
| `a1` | — | 设备信息（39 B，末尾 16 字符是 SN） |
| `1f` | — | **读索引表**（33 B：1 字节状态 + 256 位位图） |
| `a6` | `a6 <地址BE16> 00 40` | **读记录**：地址 = `0x280 + (槽位-10)*0x40`，返回 64 B 记录 |
| `a5` | 见 §4 | **写记录**（录入成功后把 UUID 写进槽位记录区） |
| `f2` | — | 验证准备（arm）；**中止命令的前缀**（见下） |
| `33 <槽位>` | 1 字节槽位 | **定向验证**：拿手指和"这一个槽位"比 |
| `f1` | — | 轮询（取上一条命令的进展） |
| `31 <槽位BE16> 0f 00 00` | — | **启动录入**到指定槽位 |
| `0c <槽位BE16> 00 01` | — | **删除**（语义见 §5，响应 `00` = 成功） |
| `f2` + `f4` | — | **中止**：`f2` 打头再 `f4`，芯片立刻从"等手指"变"空闲/已取消" |

> ⚠️ **单独发 `f4` 无效** —— 必须 `f2` 在前。这是当年试了七个候选操作码都失败的原因。

## 3. 两个状态机与状态码（实测）

### 验证 / 识别（`f2` → `33 <槽位>` → `f1` 轮询）

| 状态 | 含义 |
|---|---|
| `f0` | 等手指（**也是常态应答**：刚复位后也回它） |
| `f1` | **匹配成功**：payload 后跟 `<槽位BE16> <分数BE16>`，**分数 100 = 满分** |
| `f2` | **手指按下了但匹配不上**（★ 且"粘滞"：不换槽位就一直是它） |
| `f3` | 空闲 / 已取消 |
| `f4` | 罕见，含义未明（出现后下一步通常还是 `f2`） |

### 录入（`f2` → `31 <槽位> …` → `f1` 轮询）

| 状态 | 含义 |
|---|---|
| `e0` | 等手指 |
| `e4` | 手指放下 |
| `eb` | 采集中 |
| `e6` | **本次图像被拒**（重复/不清晰）——不是结束，**继续轮询**，提示用户挪动手指 |
| `e1` | **录入完成** ★ |
| `f3` | 已取消/空闲 |

- **除 `e1`（完成）外，所有状态都必须继续轮询**。把未知状态当错误处理会过早打断。
- 实测一次录入约需 **14 次有效按压**，每次建议挪动位置（否则 `e6` 图像重复）。
- 录入中途失败**不会**在芯片里留下垃圾槽位。

## 4. 记录区与 `a5` 写记录

每个槽位有 **64 字节记录**（只写前 36 字节有效）：

```
[0]=0x00  [1..2]=槽位LE16  [3]=0x20(长度)  [4..35]=32 字节随机数  [36..63]=0
```

- **`a5` 载荷（69 字节）**：
  `a5 <槽位×0x40 BE16> <0040 BE16> <00 | 槽位LE16 | 0x20> <32 字节> <28 字节补零>`
- **那 32 字节是主机侧生成的随机数**（拆厂商库可见 `srand(time(NULL))` + 32×`rand()`），
  作用只是"**芯片记录 ↔ 主机数据库**的对应键"，比较方式就是 `memcmp(…,32)` ——
  **不是模板、不是哈希、没有签名**，可以是你自己的任意随机数。
- 芯片在 `31` 录入时先把记录区填成 `0x33` 占位符，**等主机用 `a5` 覆盖成真值**。
  不写 `a5` 的后果：该指纹**永远验不过**，而且会被"认识这些记录的系统"当垃圾清掉
  （厂商框架的同步逻辑会删"它不认识的记录"）。
- `a6` 读记录的响应多一个前导状态字节：
  `00 00 | 槽位LE16 | 长度u8 | 数据`。

## 5. `0c` 删除的语义（实测）

- 载荷 `0c <槽位BE16> 00 01`，响应 `00` = 成功。
- **只清索引项，记录区字节还留着**（`a6` 仍读得到）。
- **索引位只能在芯片录入（`31`）时被设置 —— 主机写不回去**：
  实测把原来的 UUID 用 `a5` 写回，**索引位不会回来**。
  ⇒ 索引被清 = 这枚指纹废了，只能重新录入。
- 这就是"有记录、没索引"这种状态的来源。

## 6. 索引表（`1f`）的位图公式

payload = `状态(1 字节) + 32 字节位图`。

位图**字节 i（从 1 数）的第 b 位（LSB 优先）→ 槽位 `(i-1)*8 + b`**。

例：`00 00 04 00 …` → pay[2]=`04` → 位 2 → 槽位 **10**。

## 7. ★★ 三条最容易把人带沟里的行为

1. **芯片不做 1:N**：`33` 命令后面跟的那个字节是**目标槽位** ——
   芯片**一次只比一个槽位**。所谓"1:N 识别"要**主机自己循环**所有已占用槽位。
   （把 `33 0a` 写死 = 永远只可能匹配槽位 10。这是"加新指纹从来不成"的经典根因。）
2. **重新 arm 会重置手指检测**：芯片只在"手指**新落下**"那一刻检测。
   循环多个槽位时必须**抬手重按**；一直按着不抬，第二个槽位开始就一直是 `f0`（认为没有手指）。
3. **测指纹要等"黄灯"（= 芯片已 arm）再按**：手指如果在 arm 之前就按住，
   芯片看不到"落下"动作，直接回 `f2`——看上去像"匹配不上"，实际是时序问题。

## 8. 一个最小的"能跑通"序列（供实现参考）

```
验证一个槽位:      f2 → 33 <槽位> → f1 轮询… → f1 匹配 / f2 不匹配 / f0 超时
1:N（主机循环）:   对每个已占用槽位重复上面（每次都要用户抬手重按）
录入:              f2 → 31 <槽位BE16> 0f 00 00 → f1 轮询（e0/e4/eb/e6…）→ e1 完成
                   → a5 写 32 字节随机 UUID（否则这枚指纹不生效）
删除:              0c <槽位BE16> 00 01        （只清索引，不可逆）
中止:              f2 → f4                     （先 arm 再 abort）
```
